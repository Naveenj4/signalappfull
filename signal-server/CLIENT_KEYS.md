# Signal Client Configuration & Public Keys (CLIENT_KEYS.md)

When building custom **Signal-Android** and **Signal-Desktop** clients to connect to your private self-hosted server, the official Signal endpoints and hardcoded public keys must be replaced with the values generated for your private server.

> **CRITICAL SECURITY NOTE:**
> Keep private keys secure on the server! Only the **PUBLIC** parameters and certificates documented in this file are embedded into the client applications.

---

## 1. Public Server Parameters

| Parameter | Client Role | Server Configuration Source |
|---|---|---|
| **Server Base URL** | REST API & WebSockets | Nginx reverse proxy URL (`https://signal.yourcompany.com`) |
| **CDN / Attachment URL** | Media download & upload | MinIO / Nginx URL (`https://signal.yourcompany.com`) |
| **Unidentified Sender Trust Root** | Validates sealed sender certificates | `unidentifiedSender.certificate` (Public X.509 Certificate) |
| **ZKGroup Server Public Params** | Zero-knowledge group credentials | `zkgroup.serverPublicParams` |
| **TURN Servers** | Audio / video peer-to-peer relay | Coturn server address (`turns:signal.yourcompany.com:5349`) |

## 3. Signal-Android Modifications

In the **Signal-Android** repository (`https://github.com/signalapp/Signal-Android`):

### 1. Update Service URLs
In `libsignal/service/src/main/java/org/whispersystems/signalservice/internal/configuration/SignalServiceConfiguration.java`:
```java
// Replace official endpoints:
public static final String[] SIGNAL_SERVICE_URLS = new String[] {
    "https://signal.yourcompany.com"
};

public static final String[] SIGNAL_CDN_URLS = new String[] {
    "https://signal.yourcompany.com"
};

public static final String[] SIGNAL_CONTACT_DISCOVERY_URLS = new String[] {
    "https://signal.yourcompany.com"
};
```

### 2. Update Unidentified Sender Trust Root
In `libsignal/service/src/main/java/org/whispersystems/signalservice/api/crypto/UnidentifiedAccess.java`:
Replace `UNIDENTIFIED_SENDER_TRUST_ROOT` byte array with the public key bytes from `scripts/generate-keys.sh`.

### 3. Update ZKGroup Public Parameters
In `libsignal/service/src/main/java/org/whispersystems/signalservice/api/groupsv2/GroupsV2Operations.java`:
Replace `SERVER_PUBLIC_PARAMS` with the base64 or hex value generated above.

### 4. Enable WebSocket Fallback for Push Notifications
Signal-Android includes a built-in WebSocket background connection for devices without Google Play Services (the FOSS build flavor).
Build with:
```bash
./gradlew assembleFossRelease
```
This avoids needing Firebase Cloud Messaging (FCM). The client maintains a direct, encrypted WebSocket connection to your server for real-time incoming message notifications.

## 4. Signal-Desktop Modifications

In the **Signal-Desktop** repository (`https://github.com/signalapp/Signal-Desktop`):

### 1. Update Configuration Endpoints
In `config/production.json` or `ts/environment.ts`:
```json
{
  "serverUrl": "https://signal.yourcompany.com",
  "cdnUrl": "https://signal.yourcompany.com",
  "storageUrl": "https://signal.yourcompany.com",
  "directoryUrl": "https://signal.yourcompany.com",
  "attachmentsUrl": "https://signal.yourcompany.com",
  "unidentifiedSenderTrustRoot": "REPLACE_WITH_HEX_TRUST_ROOT"
}
```

### 2. Build the Desktop Application
```bash
npm install
npm run build
```

## 5. Verification Code for Client Login

During initial login:
1. Client enters staff phone number (e.g. `+15551234567`).
2. Server verifies the number is on the company allowlist.
3. Client prompts for the 6-digit SMS code.
4. User enters the fixed company verification code:
   ```
   123456
   ```
   (or the one-time code provided by the administrator).
5. User completes registration, generates their local identity key, and connects immediately to the company server.
